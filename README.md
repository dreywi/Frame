# Recipe Service

## Назначение
Сервис для работы с кулинарными рецептами: просмотр, поиск, подбор по
времени приготовления, пересчет ингредиентов на нужное число порций и
отзывы пользователей с оценками. Консольная версия (ПР3) дополнена
веб-интерфейсом на Django (ПР5).

## Используемые технологии
- Python 3;
- Django 5.2 -- веб-фреймворк;
- HTML -- разметка веб-страниц;
- CSS и Bootstrap 5.3 (подключен через CDN) -- оформление страниц;
- pytest -- автоматизированные тесты;
- flake8 -- проверка качества кода.

## Целевая аудитория
Домашние кулинары, которые ищут рецепты и ведут личную коллекцию, и
авторы, публикующие собственные рецепты.

## Предметная область
Рецепт описывается названием, категорией, числом порций, временем
приготовления, калорийностью порции и списком ингредиентов с количествами.
Пользователи оставляют на рецепты отзывы с оценкой от 1 до 5.

Правила:
- у пользователя может быть только один активный отзыв на рецепт;
- удаленный отзыв остается в системе, но не блокирует новый отзыв
  и не учитывается в средней оценке.

## Основные классы

### User -- пользователь
Атрибуты: `id`, `name`, `email`.

Методы:
- `from_data()` -- создание объекта из данных JSON (`@classmethod`);
- `__str__()` -- строковое представление.

Конструктор отклоняет email без `@` (`ValueError`).

### Ingredient -- ингредиент
Атрибуты: `name`, `amount`, `unit`.

Методы:
- `scaled(factor)` -- новый ингредиент с пересчитанным количеством;
- `__str__()` -- строковое представление.

### Recipe -- рецепт
Атрибуты: `id`, `title`, `category`, `servings`, `cook_time_min`,
`calories_per_serving`, `ingredients` (список объектов `Ingredient`).

Методы:
- `fits_time(limit)` -- укладывается ли рецепт в ограничение по времени;
- `speed_label()` -- быстрый / средний / долгий;
- `total_calories(servings)` -- калорийность заданного числа порций;
- `scaled_ingredients(servings)` -- ингредиенты на заданное число порций;
- `validate_servings(servings)` -- проверка числа порций (`@staticmethod`);
- `__str__()` -- строковое представление.

### Review -- отзыв
Атрибуты: `id`, `recipe` (объект `Recipe`), `user` (объект `User`),
`rating`, `comment`, `is_deleted`.

Методы:
- `delete()` -- пометить отзыв удаленным;
- `__str__()` -- строковое представление с учетом состояния.

## Взаимодействие объектов
```text
User ──оставляет──> Review ──относится к──> Recipe ──содержит──> Ingredient
```
`Review` хранит ссылки на объекты `Recipe` и `User`, поэтому их данные
доступны напрямую: `review.recipe.title`, `review.user.name`.
`Recipe` содержит список `Ingredient` (композиция).

## Страницы веб-интерфейса
| URL | View-функция | Содержимое |
|---|---|---|
| `/` | `homepage.views.index()` | описание сервиса и навигация |
| `/recipes/` | `recipes.views.recipes()` | список рецептов из `data/recipes.json` |
| `/recipes/<int:recipe_id>/` | `recipes.views.recipe_detail()` | карточка рецепта: категория, порции, время и скорость приготовления, калорийность, ингредиенты, средняя оценка |
| `/reviews/` | `reviews.views.reviews()` | список отзывов из `data/reviews.json` со статусом |
| `/reviews/<int:review_id>/` | `reviews.views.review_detail()` | карточка отзыва: рецепт (ссылка), пользователь, оценка, комментарий, статус |

Если рецепт или отзыв с указанным идентификатором не найден, страница
возвращает код 404. Для адресов без маршрута работает собственная
страница 404 (`homepage.views.page_not_found()`, подключена через
`handler404` в `recipe_service/urls.py`); она видна при `DEBUG = False`.

View-функции не дублируют предметную логику: они загружают данные
средствами ПР3 (`load_recipes()`, `load_users()`, `load_reviews()`),
находят объект по идентификатору (`find_recipe_by_id()`,
`find_review_by_id()`), вызывают методы модели (`speed_label()`,
`average_rating()`) и формируют HTML-ответ.

Все страницы собираются функцией `page()` из `homepage/views.py`: она
задает общий HTML-каркас с кодировкой, заголовком вкладки, подключением
Bootstrap и навигацией. Используются классы Bootstrap `container`,
`nav`, `list-group`, `card`, `badge`, `btn`.

## Основные операции

### В веб-интерфейсе (ПР5)
- просмотр списка рецептов;
- карточка рецепта с ингредиентами и средней оценкой;
- просмотр списка отзывов;
- карточка отзыва со связанными рецептом и пользователем.

### Только в консольной версии
Эти операции реализованы в ПР3. В веб-интерфейсе они появятся вместе
с формами и POST-запросами:
- поиск рецепта по названию;
- подбор рецептов по ограничению времени и сортировка;
- пересчет ингредиентов и калорий на заданное число порций;
- добавление рецепта;
- просмотр и добавление пользователей;
- создание отзыва с проверкой правила и удаление отзыва.

## Хранение данных
Данные хранятся в JSON-файлах:
- `data/users.json`;
- `data/recipes.json` (ингредиенты вложены в рецепт);
- `data/reviews.json`.

При загрузке данные преобразуются в объекты, при выходе из консольной
программы объекты сохраняются обратно; веб-интерфейс данные только
читает. В `reviews.json` вместо объектов хранятся идентификаторы
`recipe_id` и `user_id`; при загрузке по ним находятся объекты
`Recipe` и `User`. Отзыв с несуществующим рецептом или пользователем
пропускается. Отсутствующий файл или некорректный JSON не прерывают
работу программы.

## Назначение модулей
- `manage.py` -- утилита управления Django-проектом;
- `recipe_service/` -- пакет настроек: `settings.py` (настройки,
  зарегистрированные приложения), `urls.py` (маршруты верхнего уровня
  и `handler404`), `asgi.py`, `wsgi.py`;
- `homepage/` -- главная страница, общий каркас `page()` и страница 404;
- `recipes/` -- страницы списка и карточки рецепта;
- `reviews/` -- страницы списка и карточки отзыва;
- `main.py` -- консольная версия: меню и пользовательские сценарии;
- `models/users.py` -- класс `User` и функции работы с пользователями;
- `models/recipes.py` -- классы `Ingredient`, `Recipe` и функции работы
  с рецептами;
- `models/reviews.py` -- класс `Review` и функции работы с отзывами;
- `storage.py` -- преобразование JSON <-> объекты;
- `utils.py` -- безопасный ввод `input_int()`, `input_text()`.

Отдельного приложения для пользователей нет: в Django есть встроенная
модель `User` (`django.contrib.auth`), она понадобится вместе с
аутентификацией.

## Установка и запуск
```text
py -3 -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```
После запуска открыть в браузере http://127.0.0.1:8000/

Консольная версия:
```text
python main.py
```

## Тестирование
```text
pytest -v
```
Тесты проверяют создание объектов и их методы, операции с коллекциями,
правило активного отзыва, сохранение и загрузку JSON с восстановлением
связей, обработку некорректных данных.

## Проверка качества кода
```text
flake8 .
```
Для автоматически созданного `recipe_service/settings.py` отключена
проверка длины строки (`per-file-ignores` в `.flake8`).

## Текущее состояние и план развития
Реализовано (ПР5):
- Django-проект `recipe_service` и приложения `homepage`, `recipes`,
  `reviews`;
- маршрутизация URL двух уровней (`include()`);
- view-функции и страницы на данных ПР3;
- собственная страница 404;
- навигация между страницами, оформление Bootstrap 5.3.

  базы данных;

- пользователи и авторизация;
- разработка API;
- контейнеризация приложения;
- настройка CI/CD.
